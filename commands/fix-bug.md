# バグ修正ワークフロー

バグ `$ARGUMENTS` を以下の手順で修正してください：

## 1. 問題の理解と再現

### 1.1 情報収集
- エラーメッセージ、ログ、スタックトレースを確認
- 発生条件を特定する
- 影響範囲を確認する

### 1.2 再現テストの作成
**重要**: まず失敗するテストを書く（TDD）
```bash
# 再現テストを作成
# テストが失敗することを確認
npm run test --prefix fondesk-api -- <test-file>
```

## 2. 原因調査（Plan Mode推奨）

### 2.1 コードベースの探索
- 関連するファイルを特定
- データフローを追跡
- 依存関係を確認

### 2.2 根本原因の特定
- 症状ではなく根本原因を見つける
- エラーを隠蔽せず、原因を解決する
- 副作用がないか確認

## 3. 修正実装

### 3.1 コード修正
- 最小限の変更で修正
- 関連する箇所も同時に修正（同じバグが他にもないか）
- エラーハンドリングを適切に追加

### 3.2 テスト実行
```bash
# 再現テストが成功することを確認
npm run test --prefix fondesk-api -- <test-file>

# 既存のテストが壊れていないか確認
npm run test --prefix fondesk-api
```

## 4. エッジケースの確認

以下のエッジケースをテスト：
- [ ] null/undefined の処理
- [ ] 空配列/空文字列の処理
- [ ] 境界値のテスト
- [ ] エラー状態の処理
- [ ] 並行実行時の挙動

## 5. レビューとコミット

### 5.1 セルフレビュー
- [ ] 修正が最小限か
- [ ] 根本原因を解決しているか
- [ ] 新しいバグを作り込んでいないか
- [ ] テストが適切か
- [ ] ログが適切か

### 5.2 コミット
```
🐞 [問題の簡潔な説明]
```

## 注意事項

- **症状の抑制ではなく、根本原因の解決を優先**
- エラーを catch して無視しない
- try-catch を追加する場合は適切にログを出力
- 本番環境への影響を考慮する
