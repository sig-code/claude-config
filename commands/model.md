# Claude Code Model Switcher

ユーザーが指定したモデルに Claude Code を切り替えます。

## 使用方法
```
/model [sonnet|opus|haiku]
```

引数なしで実行した場合は、現在のモデルを表示し、利用可能なモデルの説明を提供します。

## あなたの役割

このスキルが呼び出されたとき、以下の手順を実行してください：

### 1. 引数の確認

ユーザーが指定した引数を確認します：
- 引数がない場合：現在のモデルを表示し、モデル選択のガイダンスを提供
- `sonnet`/`opus`/`haiku` のいずれか：そのモデルに切り替え
- その他の値：エラーメッセージを表示して利用可能なオプションを示す

### 2. 現在のモデル確認（引数なしの場合）

```bash
jq -r '.model' ~/.claude/settings.json
```

現在のモデルを表示し、以下の情報を提供：

**利用可能なモデル：**

| モデル | 特徴 | 推奨用途 |
|--------|------|----------|
| **Sonnet 4.5** (`/model sonnet`) | バランス型 | 通常の開発作業、コードレビュー、バグ修正 |
| **Opus 4.5** (`/model opus`) | 最高性能 | 複雑なアーキテクチャ設計、大規模リファクタリング |
| **Haiku 4.5** (`/model haiku`) | 高速・低コスト | シンプルな質問、クイック確認 |

### 3. モデル切り替え（引数ありの場合）

指定されたモデルに切り替えます：

```bash
~/.claude/switch-model.sh [sonnet|opus|haiku]
```

切り替え後、以下を明確に伝えます：

1. ✓ 切り替えが成功したこと
2. 切り替え先のモデル名とID
3. **重要**: 変更を反映するには Claude Code の再起動が必要であること
4. 現在のセッションは引き続き現在のモデル（切り替え前のモデル）で動作すること

### 4. 再起動の案内

モデル切り替え後、必ず以下を案内してください：

```
⚠️ 変更を反映するには Claude Code を再起動してください

再起動方法：
1. 現在のセッションを終了（Ctrl+D または exit）
2. 新しいセッションで `claude` を実行

新しいセッションで選択したモデルが有効になります。
```

## モデル選択のガイドライン

ユーザーが迷っている場合、以下の基準を提案してください：

### Sonnet を選ぶべき場合
- 日常的な開発タスク
- コードレビューやドキュメント作成
- バランスの取れたパフォーマンスとコスト

### Opus を選ぶべき場合
- 複雑なアーキテクチャの設計や実装
- 大規模なリファクタリング
- 高度なデバッグや問題解決
- 重要な意思決定が必要な場合

### Haiku を選ぶべき場合
- シンプルな質問や確認
- クイックなレスポンスが必要
- コスト削減が重要な場合

## エラーハンドリング

- スクリプトが存在しない場合：セットアップが必要であることを伝える
- 無効な引数：利用可能なオプション（sonnet/opus/haiku）を表示
- 実行エラー：エラーメッセージを表示し、トラブルシューティングを提案

## 例

### 例1: 現在のモデルを確認
```
/model
```
→ 現在のモデルと利用可能なモデルのリストを表示

### 例2: Opus に切り替え
```
/model opus
```
→ Opus 4.5 に切り替え、再起動を案内

### 例3: Sonnet に戻す
```
/model sonnet
```
→ Sonnet 4.5 に切り替え、再起動を案内

## 重要な注意事項

1. **このスキル実行中は現在のモデルで動作しています**
2. **切り替えは次回の Claude Code 起動時に有効になります**
3. **バックアップは自動的に作成されます** (`~/.claude/settings.json.backup`)
4. ユーザーに対して、モデル切り替え後は再起動が必要であることを強調してください
