# Bugsnag エラートリアージスキル

## 🎯 ゴール

Bugsnag MCP で直近のエラーを確認し、**「対応が必要なものはどれか」を5分で判断できる報告**を返す。

## 📋 フロー

### 1. 対象プロジェクトの確認
- `bugsnag_get_current_project` で現在のプロジェクトを確認。指定がなければ fondesk 系のプロジェクトを対象にする
- 複数プロジェクトの横断確認を頼まれたら `bugsnag_list_projects` から列挙

### 2. エラー一覧の取得
- `bugsnag_list_project_errors` で直近(デフォルト24時間、指定があればその期間)のエラーを取得
- ソート: 発生件数順 + 初回発生日時順の両方を見る

### 3. 分類(トリアージ)
各エラーを以下に分類する:

| 分類 | 判定基準 | アクション |
|---|---|---|
| 🆕 新規 | 初回発生が対象期間内 | 最優先で深掘り |
| 📈 急増 | 既存だが件数が通常比で顕著に増加 | デプロイ・外部要因との相関確認 |
| 🔁 再発 | 過去に fixed にしたものが再発生 | 修正の見直し |
| 💤 既知・定常 | 以前から一定頻度で発生 | 報告のみ(対応不要の根拠を添える) |

### 4. 深掘り(🆕新規と📈急増のみ)
- `bugsnag_get_error` → `bugsnag_get_events_on_an_error` でスタックトレース・影響ユーザー数・発生環境を確認
- 該当コード箇所をリポジトリで特定し、直近のコミット・デプロイとの関連を調べる
- 原因調査が本格化する場合は `debug-incident` スキルに切り替える

### 5. 報告テンプレート

```markdown
## Bugsnag トリアージ結果(対象: <プロジェクト> / 期間: <期間>)

### 要対応 🚨
| エラー | 分類 | 件数/ユーザー数 | 推定原因 | 関連コード |
|---|---|---|---|---|

### 経過観察 👀
- <エラー>: <理由>

### 対応不要(既知・定常) ✅
- <エラー>: <根拠>
```

## 🚫 アンチパターン

- ❌ 件数だけ列挙して分類しない → 必ず「対応要否」まで判断する
- ❌ 全エラーを深掘りして時間を溶かす → 深掘りは新規・急増のみ
- ❌ スタックトレースの生ログを長々貼る → 要点(発生箇所・条件)に要約
