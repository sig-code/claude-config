# ELI5 (Explain Like I'm 5)

引数のトピックを「そのトピックについて何も知らない人」に向けて説明するHTMLアーティファクトを作成する。

## 進め方

1. トピックの理解が浅い・最新情報が必要な場合は先に調査する（コードベース内の話ならコードを読む、一般知識ならWebSearch）
2. `artifact-design` スキルを読み込んでからHTMLを書く
3. **公開前に用語チェックを行う**（下記）
4. Artifactツールで公開し、URLを渡す

## 説明の原則

- **絵が主役、言葉は従**。各セクションは大きなインラインSVGの図解1つ＋短い文1〜2行で構成する
- 専門用語を使わない。使わざるを得ない場合は、その場で身近なものにたとえて言い換える
- 説明は「一番大事な1つのメンタルモデル」に絞る。網羅より直感の獲得を優先する
- 身近なアナロジー（郵便、レストラン、学校など）を軸に、図もそのアナロジーで描く
- 1画面1アイデア。スクロールに沿って段階的に理解が積み上がる構成にする
- 言語はユーザーの依頼と同じ言語（通常は日本語）

## 用語チェック（公開前に必ず実行）

読者は**製品名・サービス名は知っている**（Stripe、AWS、CloudWatch、Bugsnag 等はそのまま出してよい）。知らないのは**その中で何が起きているか**のほう。言い換えるのはこちらだけ。

**本文だけでなく、図のラベル・キャプション・ヘッダーの小さな添え書き・フッターの「確認方法」まで含めて**、書き終えたHTML全体を対象に確認する。ここが最も漏れやすい。

1. **技術概念を言い換える**。仕様上の名前・データ構造・処理の名前は、読者の生活語に置き換える。
   - `subscription schedule` → `予約票`
   - `フェーズが2つ` → `区間が2つ`
   - `webhook で発火` → `更新日にゲートを通ったとき`
2. **社内語・業界語を言い換える**。`本番` `ステージング` `デプロイ` `読み取り専用` などは読者の側の言葉にする。
   - `本番でまだ動いていない` → `実際のお客さまの契約では、まだ一度も動いていない`
3. **飾りのラベルも読める日本語で書く**。小さなラベル・図の注記・囲みの見出しを、ローマ字転写や意味のない大文字英字にしない。読者はローマ字を読まない。等幅フォントや字間で「伝票っぽさ」を出したいときも、文字の中身は日本語のままにする。製品名も本来の表記のまま書く（`STRIPE` ではなく `Stripe`）。
   - `MOTTOMO TAISETSU NA TEN` → `いちばん大切な点`
   - `TSUKAENAI` → `使えない`
   - `DENWA WO TOTTA TSUKI` → `電話をとった月`
4. **検算する**。書き終えたら機械的に grep して、残っていないことを確かめてから公開する。

```bash
grep -oniE "webhook|endpoint|schema|migration|本番|ステージング|デプロイ|フェーズ|エンドポイント|冪等|リトライ|バッチ" <file>
grep -onE "[A-Z]{3,}( +[A-Z]{2,})*" <file>   # ローマ字・大文字ラベルの検出
```

1つ目のヒットは、外部から読み込むフォントやライブラリのURLなど画面に出ない箇所を除き、すべて言い換える。2つ目のヒットは、`STEP` のような誰でも読める短い英単語と画面に出ないコードを除き、すべて日本語に直す。

## 図のスタイル

- SVGは大きく（幅いっぱい）、要素は少なく、ラベルは大きな文字で
- 矢印・番号で「流れ」を示す。静的な構成図より「何がどう動くか」を描く
- 色は意味を持たせて3色程度まで。ライト/ダーク両テーマで読めるようにする
- 図の中の文字はすべて読者が読める日本語にする。「ラベルらしさ」のためにローマ字や大文字英字を置かない
