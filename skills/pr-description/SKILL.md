# PRディスクリプション作成スキル

## 🎯 ゴール

レビュワーが **「Why → 影響範囲 → 重点レビュー箇所」を3分以内に掴める** PRを作る。

## 🚨 最重要ルール（必ず守る）

1. **Why ファースト**: 1行目で「何を解決するPRか」を述べる
2. **PRサイズに応じてテンプレを選ぶ** （後述のS/M/L）。小さいPRに重いテンプレは使わない
3. **GitHubへ直接投稿する**: `gh pr create` / `gh pr edit` で本文を直接渡す。一時ファイル経由のコピペは原則禁止
4. **差分の事実だけを書く**: 推測や将来計画はカットし、`📝 補足` に最小限だけ残す
5. **Mermaidは複雑な分岐があるときだけ**: 単純な順次処理ならASCIIで十分
6. **整合確認を依頼されたら**: `gh pr view --json body,files` と実際の差分を突き合わせ、本文に無い変更・本文にあるが差分に無い記述を列挙して修正案を出す

---

## 📐 サイズ別テンプレート

PR の差分量とリスクで判断する:

| サイズ | 目安 | テンプレ |
| --- | --- | --- |
| **S** | 〜100行 / 単一ファイル / 低リスク | `概要` + `変更点` のみ |
| **M** | 〜500行 / 複数ファイル | S + `背景` + `レビューポイント` |
| **L** | 500行〜 / 仕様変更 / Webhook・課金・認証 | M + `処理フロー図` + `テスト観点` |

### S テンプレ

```markdown
## 概要

[1-2行で「何を」「なぜ」]

## 変更点

- [ファイル/関数名]: [変更内容]
- ...

closes #ISSUE
```

### M テンプレ

```markdown
## 概要

[1-2行で「何を」「なぜ」]

## 背景

- **問題**: [現状の課題]
- **影響**: [放置するとどうなるか]

## 変更点

- [ファイル/関数名]: [変更内容]
- ...

## レビューポイント

- [ ] [特に見てほしい観点1]
- [ ] [特に見てほしい観点2]

closes #ISSUE
```

### L テンプレ

```markdown
## 概要

[1-2行で「何を」「なぜ」]

## 背景

- **問題**: ...
- **影響**: ...
- **採用しなかった案**: [あれば] ...

## 処理フロー

### Before
A → B → C ❌ (ここで失敗)

### After
A → **B'** → C ✅

## 変更点

### `path/to/file.ts`
- [変更内容]
- [影響範囲]

## テスト

- [x] ユニットテスト追加 (`xxx.spec.ts`)
- [x] ローカルで動作確認（手順を記載）
- [ ] ステージング検証

## レビューポイント

### ロジック
- [ ] ...

### 互換性・データ整合性
- [ ] ...

## 📝 補足

- [既知の制約・後続タスク]

closes #ISSUE
```

---

## ✅ 投稿前チェックリスト

- [ ] 1行目を読むだけで「何のPRか」わかる
- [ ] PRサイズと選んだテンプレが合っている
- [ ] 関連 Issue を `closes #ISSUE` で紐付けた（Issue がある場合。Linear は `closes <PREFIX>-<番号>`）
- [ ] スクリーンショット/動画が必要なUI変更で、添付されている
- [ ] 破壊的変更・マイグレーション・課金関連は **L テンプレ** にした
- [ ] レビューポイントが具体的（「動作確認」のような曖昧表現は禁止）

---

## 🤖 投稿フロー（推奨）

### 新規作成

```bash
gh pr create --title "🚀 ○○機能を追加" --body "$(cat <<'EOF'
## 概要
...
EOF
)" --draft
```

### 既存PRの本文更新

```bash
gh pr edit <番号> --body "$(cat <<'EOF'
...
EOF
)"
```

## 🚫 アンチパターン

| ❌ 悪い例 | ✅ 良い例 |
| --- | --- |
| `修正しました` | `Stripe webhook の署名検証エラーを修正` |
| 全PRに重厚なテンプレを適用 | サイズに応じて S/M/L を使い分け |
| `動作確認OK` だけ書く | どの環境で何を確認したか具体的に書く |
| 一時 `.md` ファイル経由でコピペさせる | `gh pr create --body` で直接投稿 |
| 想定リスクを延々と列挙 | 実際の差分に紐づくレビューポイントだけ書く |
