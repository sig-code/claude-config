# PR レビュー

PR `$ARGUMENTS` を以下の手順でレビューしてください。**出力はすべてチャットへの表示のみ。GitHubへのコメント投稿・ラベル付与・承認操作は一切行わないこと。**

## 1. PR 情報の取得

```bash
gh pr view $ARGUMENTS --json title,body,files,commits,additions,deletions,author,baseRefName,headRefName
```

変更ファイルを全件取得し、それぞれ Read ツールで内容を読む。
ファイル数が多い場合は重要度の高いもの（ロジック・テスト）から優先的に読む。

## 2. 出力フォーマット

以下のセクションをすべて含めてチャットに出力してください。

---

### 📋 PR 概要

| 項目 | 内容 |
|------|------|
| タイトル | （タイトル） |
| 作成者 | （author） |
| ブランチ | `headRef` → `baseRef` |
| 変更規模 | +追加行 / -削除行、変更ファイル数 |
| 目的 | （PR 本文の概要を1〜2文で要約） |

---

### 🗺️ ファイル構成と役割

変更されたファイルを列挙し、それぞれの役割を1行で説明する。

```
変更ファイル一覧:
  path/to/file.ts       +XX / -YY  （役割の説明）
  path/to/file.test.ts  +XX / -YY  （テストの説明）
```

---

### 🏗️ 全体構造

コードの全体像をツリーや箇条書きで示す。関数・クラス・処理ブロックの階層を明示する。

例:
```
ファイル名.ts
├── 定数定義
├── メイン関数
│   ├── 処理A
│   └── 処理B（今回追加）
│       ├── フォールバック1
│       └── フォールバック2
└── ヘルパー関数（今回追加）
```

---

### 📖 コード解説（セクションごと）

変更されたコードを意味のあるブロックに分けて、それぞれ:
1. **該当コードを抜粋**（省略せず表示）
2. **何をしているか**を説明
3. **具体的な数値・データ例**を使って動作を示す

変更前後がある場合は diff 形式で示す。

---

### 🔄 処理フロー（具体例付き）

実際のデータが流れる様子を図示する。
- 正常系（ハッピーパス）
- 異常系・エッジケース

例:
```
入力: Call ID=[1, 2, 3]
  ↓
deleteMany([1, 2, 3]) → ✅ 成功 → 完了
                      → ❌ エラー → 個別削除へ
                          ↓
                          delete(1) → ✅ 成功
                          delete(2) → ❌ エラー → 自己修復 → 再delete → ✅
```

---

### ✅ 良い点

各点を具体的なコード箇所（ファイル:行番号）とともに挙げる。

---

### ⚠️ 気になる点・改善提案

各点について:
- **何が気になるか**（コード箇所を明示）
- **どういう状況で問題になるか**（具体例）
- **改善案**（あれば）

致命度を以下で分類する:
- 🔴 **ブロッカー**: マージ前に必ず直すべき
- 🟡 **要確認**: 意図を確認したい・将来リスクになりうる
- 🟢 **Nice to have**: 軽微・好み・次回でも可

---

### 🧪 テスト評価

- テストが追加されているか
- 正常系・異常系・エッジケースのカバレッジ
- モック戦略の妥当性
- 「このテストがあれば本番バグを防げるか」という観点での評価

---

### 🏁 総合判定

最後に以下の形式で判定を出力する:

```
判定: ✅ LGTM / 🟡 条件付き LGTM / 🔴 要修正

理由: （1〜3文で）

マージ前に対応が必要な点:
  - （ブロッカーがある場合のみ列挙、なければ「なし」）
```

---

## 注意事項

- **GitHub への投稿（コメント・approve・request changes）は絶対に行わない**
- ファイルの編集・コミット・プッシュも行わない
- すべての出力はチャット表示のみ
- コードは省略せず、実際の内容を抜粋して示す
- 抽象的な説明より「具体的な値・例」を優先する

## GitHub へコメントを投稿する場合

ユーザーから明示的に「GitHub へ投稿してほしい」と依頼された場合のみ投稿する。
その際は、コメント末尾に必ず以下を付与すること:

```
🤖 Generated with Claude Code
```
