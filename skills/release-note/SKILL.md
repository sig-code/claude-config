# リリースノート作成

タグ間のコミットから、CS・ビジネス側が読む日本語のリリースノートを書き、Slack 投稿文として渡す。

## 投稿先と接頭辞

| リポジトリ | 絵文字 | 投稿先 |
| --- | --- | --- |
| fondesk-ivr | `:ivr:` | #fondesk-ivr (C064N6SLM36) |
| fondesk | `:pelican:` | #fondesk (CE0FT6881) |

## 手順

1. 範囲を特定する

```bash
git fetch --tags -q && git tag --sort=-creatordate | head -5
git log --oneline <前タグ>..<最新タグ>
```

前回の投稿以降に複数タグが出ている場合はまとめる（`v12.104.14 〜 v12.104.17 をリリースしました`）。前回投稿は Slack の当該チャンネルで「をリリースしました」を検索して確認する。

2. 各コミットの実際の変更を `git show` や PR で確認する。コミットメッセージだけで書かない。
3. 下記フォーマットで書く。
4. **投稿はユーザーの確認を取ってから行う。** 文面を提示して承認を得る。

## フォーマット

```
:ivr: v2.26.7 をリリースしました。（:claude:AI によるリリースノート）

今回のリリースは、〜です。お客様の画面や操作に変わるところはありません。

:bug: 不具合修正

■ 1着信に対してメール通知が複数届く問題を修正

• これまでは録音が0秒の通話で、通知処理が繰り返し実行されることがありました
• 〜のため、1着信につき1通知に戻っています
```

- 冒頭の1〜2文で「何のリリースか」と「お客様影響の有無」を必ず書く
- セクション見出しの絵文字: `:sparkles:` 新機能 / `:bug:` 不具合修正 / `:rotating_light:` 障害検知の強化 / `:lock:` セキュリティ対応 / `:package:` 依存パッケージの更新 / `:telephone_receiver:` AIオペレーターの応対改善
- `■` = 変更1件の見出し（1行で何が変わったか）、`•` = その詳細
- パッケージ更新だけの軽微なリリースは概要文を省き、箇条書き1行で済ませる（例: `• 42個の依存パッケージを更新しました`）

## 書き方

- 読み手は CS・ビジネス側。関数名・テーブル名・PR 番号などの実装用語は書かない
- 「何が起きていたか → どう変わったか」の順で、お客様から見た事象で書く
- 判断の理由（なぜその挙動にしたか）は1行添えると問い合わせ対応で使える
- 障害起因の修正は、お客様への案内が必要かを一言添える
